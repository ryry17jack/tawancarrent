# ตะวันรถเช่าหาดใหญ่ — tawancarrent.com

Astro site built from the Claude Design canvas
[Tawan Car Rent - Site (1b)](https://claude.ai/design/p/491363b1-dc11-4da0-ad8b-249a15bab301),
deployed as static files on Cloudflare Workers (Static Assets).

## Commands

| Command              | What it does                                        |
| -------------------- | --------------------------------------------------- |
| `npm run dev`        | Dev server on http://localhost:4321                  |
| `npm run build`      | Build the static site into `dist/`                   |
| `npm run preview`    | Serve `dist/` locally                                |
| `npm run cf:preview` | Build, then serve `dist/` through the Workers runtime|
| `npm run cf:deploy`  | Build, then `wrangler deploy`                       |
| `npm run deploy`     | `wrangler deploy` alone (the CI deploy step)         |
| `npx astro check`    | Type-check `.astro` templates                        |
| `npm run og`         | Regenerate `public/og.jpg`, the social card          |

See [Testing locally with Docker](#testing-locally-with-docker) to run it in a container instead.

## Testing locally with Docker

Nothing needs to be installed on the host but Docker.

```bash
docker compose up                                   # dev server → http://localhost:4321
docker compose --profile preview up preview         # built site → http://localhost:8080
```

**`dev`** runs `astro dev` with the source bind-mounted, so edits on the host
reload in the browser. `node_modules` lives in a named volume — the container's
Linux binaries (sharp, esbuild) must not be shadowed by a Windows-built copy.
Because bind mounts on Windows and macOS don't forward inotify events into a
container, `DOCKER_POLLING=1` switches Vite's watcher to polling; that env var
is the only thing `astro.config.mjs` reads it for.

**`preview`** builds the site and serves it through nginx with
[`docker/nginx.conf`](docker/nginx.conf), which mirrors how Cloudflare
serves `dist/`: `/cars` 301s to `/cars/`, unknown paths return the custom
`404.html` with a 404 status, `/_astro/*` is cached immutable for a year, and the
security headers match `public/_headers`. That file is duplicated by hand —
nginx cannot read `_headers`, so **edit both together**.

After changing dependencies, rebuild and reset the module volume:

```bash
docker compose down -v && docker compose up --build
```

> On Windows, `localhost` resolves to `::1` before `127.0.0.1`. If a stray host
> process is already bound to the same port on IPv6, curl and the browser will
> reach *it* instead of the container, which looks exactly like a broken mount.
> `netstat -ano | findstr :4321` shows who actually holds the port.

## SEO

Every route ships a Thai `<title>`, meta description, canonical, `hreflang` +
`x-default`, Open Graph and Twitter card tags, and `robots` with
`max-image-preview:large`. `/404` is `noindex, follow` and excluded from the
sitemap.

**Structured data** is one `@graph` per page (`AutoRental` → `WebSite` →
`WebPage`, plus `BreadcrumbList` on subpages), with a second `ItemList` of
`Vehicle` + `Offer` on `/cars/`. The offers carry
`businessFunction: LeaseOut` and a per-`DAY` `UnitPriceSpecification`, so the
daily rate is not read as a purchase price. Validate with the
[Rich Results Test](https://search.google.com/test/rich-results).

**Fonts are self-hosted** via `@fontsource-variable`, so there is no
render-blocking request to `fonts.googleapis.com` and no third-party connection
on the critical path. The `wght.css` files carry every subset behind
`unicode-range`, so a Thai page fetches Thai + Latin (~89 KB) and skips the
rest. They land in `/_astro/` and inherit the year-long immutable cache.

**The social card** is `public/og.jpg`, generated by `npm run og`. It is
committed as a static asset rather than built, because text rasterisation
depends on system fonts — running the generator inside the Debian container
would produce tofu boxes. **Replace it with a real photo of the fleet** when
one is available; a photo will outperform a typographic card.

### Before this ranks — three things only the owner can do

1. **Fill in `placeDetails` in `src/data/site.ts`** — street address, postal
   code, latitude/longitude and a Maps link. They are `null` today, so those
   fields are omitted from the JSON-LD rather than guessed. Local ranking leans
   heavily on a complete, consistent address.
2. **Claim the Google Business Profile** for หาดใหญ่ and make the name, address
   and phone match this site *character for character*. Inconsistent NAP data is
   the usual reason a local business does not appear in the map pack.
3. **Verify the domain in Google Search Console** and submit
   `https://tawancarrent.com/sitemap-index.xml`.

### Deliberately not marked up

The review scores on `/reviews/` (4.9, 320+ reviews) are **not** wrapped in
`aggregateRating` / `Review` schema. Google does not allow self-serving
reviews — reviews about a business, hosted on that business's own site — to
produce review rich results for `LocalBusiness`, and marking them up invites a
manual action. Ratings collected on the Google Business Profile show up in
search on their own. Leave this alone unless the reviews move to a
third-party platform.

## Deploying to Cloudflare Workers

The site is fully prerendered, so there is no server code at all: [`wrangler.toml`](wrangler.toml)
declares an `[assets]` directory and no `main`, and Workers Static Assets serves
`dist/` off the edge.

**Git integration (recommended).** In the Cloudflare dashboard: *Workers &
Pages → Create → Workers → Import a repository*, pick this repo, then set

- Build command: `npm run build`
- Deploy command: `npm run deploy`
- Node version: `22` (set `NODE_VERSION=22` under environment variables)

The Worker name in the dashboard must match `name` in `wrangler.toml`, or the
deploy step creates a *second* Worker under the config's name. Every push to
`main` publishes; other branches get preview URLs.

Do not reach for `wrangler pages deploy` here — this is a Worker, not a Pages
project, and that command fails with *"The Pages project ... does not exist."*
The reverse trap is louder than it looks: while `wrangler.toml` still carried
`pages_build_output_dir`, plain `wrangler deploy` warned *"you have run
`wrangler deploy` on a Pages project"* purely because of that one config key,
even though no Pages project ever existed. Both messages describe the config
file, not the account.

**Direct upload.** `npm run cf:deploy` (needs `npx wrangler login` once).

**Custom domain.** *Worker → Settings → Domains & Routes → Add → Custom domain →*
`tawancarrent.com`. Keep `site` in `astro.config.mjs` matching the live domain —
it is what canonical URLs and `sitemap-index.xml` are built from.

`public/_headers` sets the security headers and caches hashed `_astro/*` assets
for a year; Astro copies it into `dist/`, and the assets runtime applies it.

## Layout of the code

```
src/
  data/site.ts        Locale-neutral facts: contacts, fleet structure, prices
  i18n/
    types.ts          The Dict shape — every string the site renders
    th.ts / en.ts      Thai and English copy, both typed against Dict
    index.ts          pathFor(), switchLocalePath(), locale helpers
  views/              One component per page, rendered by both locales
  pages/              Thin routes: /… (Thai) and /en/… (English), plus 404
  layouts/Base.astro  <head>, fonts, JSON-LD, header + footer frame
  components/         Header, Footer, Media (photo slot), CarTile
  styles/
    ds-modernist.css  Design-system tokens, mirrored from the design project
    site.css          Page-level classes translated from the mockup's inline styles
public/               og.jpg, favicon, robots.txt, Cloudflare _headers
```

## Languages

Thai is the default locale and stays unprefixed (`/cars/`); English lives under
`/en/` (`/en/cars/`). Both are prerendered — 11 pages in total.

Each page is written once in [`src/views/`](src/views/) and rendered by two
three-line route files, so the markup cannot drift between languages. The route
files are the only thing duplicated:

```astro
---
import Cars from '../../views/Cars.astro';
---
<Cars lang="en" />
```

**Editing copy.** All strings live in [`src/i18n/th.ts`](src/i18n/th.ts) and
[`src/i18n/en.ts`](src/i18n/en.ts), both typed against the `Dict` interface in
[`types.ts`](src/i18n/types.ts) — a missing or misspelled key is an
`astro check` error, not a page that renders `undefined`.

**Prices are not translated.** Rates, the fleet and contact details live once in
[`src/data/site.ts`](src/data/site.ts), keyed by id, and the dictionaries supply
only names and descriptions. A price change is one edit and cannot leave the two
languages disagreeing.

**The header toggle** links to the *current page* in the other language, not to
its home page — derived from the path by `switchLocalePath()`, so adding a route
needs no lookup table. Each page also emits `hreflang` for `th`, `en` and
`x-default` (Thai), pointing at that page's own counterparts, and the sitemap
carries the same reciprocal alternates.

**Adding a route.** Add the key to `routes`/`routePaths` in `site.ts`, add its
strings to both dictionaries, create the view, then the two route files.

**The 404 is bilingual.** `not_found_handling = "404-page"` serves one
`404.html` for every unmatched path including those under `/en/`, so it carries both languages rather
than guessing.

### Adding real photos

Every image slot renders `src/components/Media.astro`. With no `src` it draws the
design's hatched placeholder and its caption; give it a `src` and it renders a
lazy-loaded `<img>` that fills the same box. Drop files into `public/` (e.g.
`public/cars/eco-1200.jpg`) and set `photo` on the car in `site.ts`, or pass
`src` directly for the hero, map, QR and gallery slots.

## Notes on the translation from the design

- The mockup switched pages with client-side state (`sc-if` on `isHome`,
  `isCars`, …). Here each of those is a real prerendered route, so every page has
  its own URL, title, description and canonical — which is what the shop needs
  for search.
- The canvas is a fixed 1280px artboard, but the site runs **full width** — the
  layout fills the browser window at any size. That is `--page: 100%` in
  `site.css`; set it back to `1280px` to restore the centred artboard. The
  gutter widens to 48px past 1600px and 64px past 2200px so the hairline rules
  do not run flush to the screen edge.
- Below desktop, the design adapts: display type uses `clamp()`, the 4-up stat
  band folds to 2-up, card grids to 1–2 columns, and the nav becomes a
  horizontally scrollable row under the logo.
- `build.cssTarget` in `astro.config.mjs` is load-bearing. Without it Lightning
  CSS emits media-query range syntax (`@media (width<=700px)`), which Safari and
  iOS below 16.4 ignore — every breakpoint above would silently fail and phones
  would get the desktop layout.
- The fleet filter chips are inert in the mockup. Here they filter the grid with
  a small inline script; with JavaScript off every car stays visible.
- Thai text sets in Anuphan and Latin display runs in Archivo, matching the
  mockup's font stacks (Archivo carries no Thai glyphs).
- The home page's "แอดไลน์ @tawan8118" button goes to `/contact/`, following the
  mockup's own flow. Point it at `business.lineUrl` instead if you would rather
  send people straight into LINE.
- TH | EN in the header was a static indicator in the mockup. It is now a real
  toggle between the two locales — see [Languages](#languages). The English copy
  is a translation of the Thai, since the design supplied only Thai.
